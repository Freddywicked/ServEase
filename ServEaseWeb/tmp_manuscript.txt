4.4.7  Functional  and  Non-Functional  Requirements   
Functional  Requirements   1.  The  system  shall  allow  Customers,  Service  Providers,  and  admins  to  register  and  log  in  with  
role-based
 
access.
 
 
2.  The  system  shall  allow  Service  Providers  to  register  and  submit  credentials  for  verification.  
3.  The  system  shall  allow  users  to  manage  and  edit  their  profile.   
4.  The  system  shall  allow  the  Customers  to  submit  a  service  request  with  diagnostic  form  and  device  
images.
 
 
5.  The  system  shall  run  an  AI  fault  diagnosis  /  smart  recommender  to  suggest  a  probable  issue  category  \n\f\n 
based  on  the  Customer’s  description.   
6.  The  system  shall  locate  and  display  nearby  verified  Service  Providers  based  on  the  Customer’s  
location
 
and
 
the
 
diagnosed
 
category.
 
 
7.  The  system  shall  allow  Service  Providers  to  accept  or  reject  a  forwarded  service  request.  
8.  The  system  shall  allow  Service  Providers  to  submit  a  pre-repair  quotation.  
9.  The  system  shall  allow  Customers  to  approve  or  reject  a  submitted  quotation.   
10.  The  system  shall  automatically  create  a  booking  record  upon  quotation  approval.   
11.  The  system  shall  allow  Service  Providers  to  update  repair  progress  in  real  time.  
 12.  The  system  shall  broadcast  real-time  status  updates  to  the  Customer.   
13.  The  system  shall  allow  Service  Providers  to  request  additional/unexpected  payment  for  extra  parts  
mid-repair,
 
pausing
 
progress
 
until
 
Customer
 
approval.
 
 
14.  The  system  shall  support  staged  payments,  payment  options  and  generate  digital  receipts  upon  
payment
 
completion.
 
15.  The  system  shall  allow  Customers  to  rate  and  review  Service  Providers  after  job  completion.   
16.  The  system  shall  analyze  review  text  using  an  AI  sentiment  analysis  model  and  update  the  Service  
Provider’s
 
aggregate
 
rating/sentiment
 
score.
 
 
17.  The  system  shall  allow  in-app  messaging  between  Customers  and  Service  Providers.  
Non-Functional  Requirement   
Category   Requirement  
Performance   Real-time  status  updates  shall  reflect  within  a  few  seconds  of  a  Service  Provider’s  status  change.  
Scalability   The  system  shall  support  concurrent  use  by  multiple  Customers  and  Service  Providers  without  service  degradation.  
Availability   The  system  shall  be  accessible  via  mobile  (primary)  and  web  (alternative)  platforms  with  minimal  downtime.  \n\f\n 
Security   User  credentials  and  payment  data  shall  be  encrypted  in  transit  and  at  rest;  role-based  access  control  shall  restrict  data  visibility.  
Usability   The  interface  shall  be  simple  and  intuitive  enough  for  non  technical  users.  
Reliability   Payment  and  booking  transactions  shall  be  logged  and  recoverable  in  case  of  failure.  
Accuracy   The  AI  fault  diagnosis  and  sentiment  analysis  outputs  shall  bepresented  with  a  confidence/sentiment  score  rather  than  as  absolutefact.  
Maintainability   The  system  shall  follow  a  three-tier  architecture  (presentation,  application,  data)  to  allow  independent  updates  to  each  layer.  
Compatibility   The  mobile  app  shall  run  on  both  Android  and  iOS  via  React  Native.  
Privacy   Location  data  used  for  the  repairman  locator  shall  only  be  accessed  with  user  consent.

System  Usability  Scale  (SUS)   
The  SUS  questionnaire  has  a  ten-item  linear  scale.  Each  question  is  scored  from  1  to  5.  A  score  of  1  
indicates
 
strong
 
disagreement,
 
while
 
a
 
score
 
of
 
5
 
indicates
 
strong
 
agreement.
 
Below
 
is

template
 
for
 
the

1.  I  would  like  to  use  this  system  frequently.   
2.  The  system  was  unnecessarily  complex.       
3.  The  system  was  easy  to  use.   \n\f\n 
4.  I  think  that  I  would  need  the  support  of  a  technical  person  to  be  able  to  use  this  system.   
5.  The  features  in  this  system  were  well  integrated.   
6.  I  thought  there  was  too  much  inconsistency  in  this  system.   
7.  I  think  that  most  people  would  learn  to  use  this  system  very  quickly.   
8.  I  found  the  system  very  cumbersome  to  use.   
9.  I  felt  very  confident  using  the  system.
